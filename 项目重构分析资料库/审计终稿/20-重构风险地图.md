## 0. 风险等级与分类约定

| 维度 | 代号 | 含义 |
|---|---|---|
| 资金/数据完整性 | FIN | 资金安全、账务正确、数据一致性 |
| 安全/权限 | SEC | 鉴权、越权、凭据泄露 |
| 实时通信 | RT | SSE/推送/状态传播 |
| 前端隐藏契约 | FE | 前后端隐式文本/字段/状态码契约 |
| 可测试性 | TEST | 重构安全网缺失 |
| 部署/运维 | OPS | 备份/回滚/配置/DR |
| 性能扩展 | PERF | 水平扩展、并发、配额 |

**字段定义**
- **触发条件**：何时会真实引发故障。
- **爆炸半径**：故障影响范围（单用户 / 全站 / 资金池 / 数据持久性）。
- **缓解前置条件**：重构动手前必须先满足的前置（如加唯一约束、补字符化测试、锁定契约）。
- **硬阻塞 / 可并行**：
  - **🔴 硬阻塞** = 开始规划正式重构前**必须清除或锁定**（否则重构无安全基线、或会持续资损/被接管）。
  - **🟢 可并行** = 可在重构过程中随模块一并处理，不阻断启动。

**证据等级 + 置信度**统一记为：`【证据等级】/ 置信度`，如 `源码已证实 / HIGH`。

## 2. 资金 / 数据完整性维度（单列重点）

> 资金为最高风险域。下列 FIN-01~FIN-05 为已知 P0，**当前仍在持续资损/账务失真**，是重构前置的"止血点"。

### FIN-01 · `credit_transactions` 缺 `(ref,kind)` 唯一约束 → TOCTOU 并发双退
- **描述（现象+根因）**：`billing.cjs:_hasPosted(ref,kind)` 为 `SELECT 1 ... WHERE ref=$1 AND kind=$2 LIMIT 1` 后再 `INSERT`，两步非原子；`credit_transactions` 仅有非唯一索引 `ix_ct_ref`（`server.js:248`），无 `(ref,kind)` 唯一约束（04-§6.1）。并发或崩溃重试下两次 `release`/`commit` 可同时越过 `_hasPosted` 检查 → 余额被多退一次。
- **触发条件**：同一 `ref`（任务/订单）并发释放、或进程在 `INSERT` 前崩溃后重试。
- **爆炸半径**：单用户余额虚增；规模化后全站积分池失真、可被刷。
- **缓解前置条件**：加 `UNIQUE(ref,kind)` 约束 + `INSERT ... ON CONFLICT DO NOTHING`；把 commit/release 包进真实事务（07-§9）。
- **硬阻塞 / 可并行**：🔴 **硬阻塞**（资损风险，重构前必须止血）。
- **证据等级 + 置信度**：【源码已证实】+【数据库已证实】 / HIGH（07-§6.2、04-§6.1、15-P0-1）。

### FIN-02 · `consumption_ledger` 幂等键非唯一 → 并发双记账
- **描述**：`accounting.recordConsumption` 同键 `SELECT`→`INSERT` 无事务；`idempotency_key` 仅非唯一索引 `ix_cl_idem`（`server.js:656`）。并发同键可双插 → 经营看板 `margin_cents` 虚高、成本失真（07-§6.3）。
- **触发条件**：同一消耗事件并发入账（如重试/并发请求）。
- **爆炸半径**：账务/盈亏看板失真；影响管理层对账与分成决策。
- **缓解前置条件**：加 `UNIQUE(idempotency_key)` + `ON CONFLICT DO NOTHING`（07-§9）。
- **硬阻塞 / 可并行**：🔴 **硬阻塞**。
- **证据等级 + 置信度**：【源码已证实】+【数据库已证实】 / HIGH（07-§6.3、04-§6.2、15-P0-2）。

### FIN-03 · 失败键复用不清理 `credit_transactions` → 永久漏退积分
- **描述**：`server.js:2415-2418` 重试 `failed` 任务仅 `releaseCredits` + 删 `generation_tasks` 行，**不清理**对应 `credit_transactions` 行。第二次若再失败，`releaseCredits` 的 `_hasPosted` 命中第一次残留 release 行 → 返回 `true` → 跳过释放，用户**永久损失 `cost` 积分**（07-§6.1）。
- **触发条件**：同一任务首次失败→重试→再次失败。
- **爆炸半径**：单用户积分永久损失（不可恢复）。
- **缓解前置条件**：失败键复用时清理旧 `credit_transactions` 行，或改用 `ON CONFLICT`（07-§9）。
- **硬阻塞 / 可并行**：🔴 **硬阻塞**。
- **证据等级 + 置信度**：【源码已证实】 / HIGH（07-§6.1）。

### FIN-04 · T1 bug → failover 空转 → 积分永不释放（与 PERF-03 同源）
- **描述**：`minimax.cjs:85` / `volcano.cjs:121` 在生成端明确失败时返回 `status:'error'`（非 `'failed'`）。`attemptOnAccount`（`dispatcher.cjs:509`）把非 `failed` 一律当瞬时错误 markReject 并**切下一账号新建真实 provider 任务**。若所有 provider 失败 → 多轮 `null` → `throttled` → 入 `waiting` → **积分永不释放、任务永不标 failed**（看门狗仅回收 `running`，明确不碰 `waiting`）（06-§10、09-§5）。
- **触发条件**：MiniMax/Volcano 明确失败（如内容违规/参数错）。
- **爆炸半径**：单用户 held 积分永久占坑；provider quota 被空耗；任务卡 `waiting` 无人复核。
- **缓解前置条件**：适配器在明确失败时返 `'failed'`（与 agnes/generic 对齐）；补字符化测试锁定（06-§10、09-§5）。
- **硬阻塞 / 可并行**：🔴 **硬阻塞**（持续资损 + quota 浪费）。
- **证据等级 + 置信度**：【源码已证实】 / HIGH（06-§10、09-§5、02-摘要2）。

### FIN-05 · webhook 绕过 billing 裸 SQL 入账 → 两套记账语义漂移
- **描述**：`webhook.cjs:128-168` 直接 `UPDATE users SET recharge_credits=...` 裸 SQL 入账，**完全未引用 `billing.cjs`**（Grep 证实）。未复用 billing 的双池/幂等键逻辑；本金与 bonus 同入 `recharge` 池。两套记账语义天然漂移（08-§7）。
- **触发条件**：任何真实支付回调入账。
- **爆炸半径**：账务语义不一致；未来若 billing 规则变更，webhook 路径不会同步，埋下双账隐患。
- **缓解前置条件**：统一入账路径（复用 billing 入账方法）或显式记录"双路径"为已知设计并加契约测试（08-§10）。
- **硬阻塞 / 可并行**：🔴 **硬阻塞**（重构若动 billing，必须先收敛路径）。
- **证据等级 + 置信度**：【源码已证实】 / HIGH（08-§7、02-摘要3）。

## 3. 安全 / 权限维度（单列）

> 当前部署以 dev 模式运行（`.env` 无 `NODE_ENV`），`devTokenEnabled=true`，下列 SEC-01/02/05 可被**未登录远程利用**。

### SEC-01 · `/api/token` 公开返回 system token → 全站管理员接管
- **描述**：`server.js:3623` 位于 `http.createServer` 最外层、早于鉴权网关，无条件 `sendJSON(200,{token:API_TOKEN})`。`appGateway`（`server.js:1276`）在 `devTokenEnabled` 时，只要 `Authorization: Bearer <API_TOKEN>` 即置 `req.user={role:'system'}`；`requireAdmin` 放行 `admin||system`（03-§3.1、10-P0-A）。
- **触发条件**：任何人 `GET /api/token`（无需登录）→ 带 Bearer 调任意 `/api/admin/*`。
- **爆炸半径**：**全站**。读全量用户/积分、改角色、手动充值、删用户、看账务、清错误日志。
- **缓解前置条件**：移除公开返回；system 令牌仅限服务端内部/启动注入；前端鉴权改纯会话 cookie；生产必须 `NODE_ENV=production` 且不显式注入 `API_TOKEN`（03-§3.1）。
- **硬阻塞 / 可并行**：🔴 **硬阻塞**（远程未授权提权，最高危）。
- **证据等级 + 置信度**：【源码已证实】+【配置文件已证实】 / HIGH（03-§3.1、10-P0-A）。

### SEC-02 · JWT 默认弱密钥可伪造任意身份
- **描述**：`auth.cjs:9` `SECRET = process.env.JWT_SECRET || 'dev-only-change-me'`。活动 `.env` 无 `JWT_SECRET`（13-§2.2），回退公开常量。攻击者可离线签发任意 `sub`/`role:'admin'` 的合法 sid cookie；生产自检仅 `console.warn` 不 fail-closed（10-P0-B）。
- **触发条件**：部署未注入强 `JWT_SECRET`（当前运行实例即此状态）。
- **爆炸半径**：**全站认证绕过**，任意用户/管理员身份伪造。
- **缓解前置条件**：生产注入强随机 `JWT_SECRET` 并 fail-closed（缺失即拒绝启动）（10-P0-B）。

## 10. 审计发现摘要（最关键 5 条风险）

1. 🔴 **【P0·安全】`/api/token` 公开返回 system token + dev 模式运行 → 全站管理员接管**
   `/api/token`（`server.js:3623`）在鉴权网关前无条件返回全局令牌；`devTokenEnabled=true`（`.env` 无 `NODE_ENV`）下，任何匿名用户取令牌即获 `system` 身份，绕过全部 `requireAdmin`。**当前运行实例即处于此可被远程接管状态**。（SEC-01、OPS-05）

2. 🔴 **【P0·资金】计费/账务无 DB 唯一约束 + 无事务 → TOCTOU 双退/双记账 + 漏退**
   `credit_transactions(ref,kind)` 与 `consumption_ledger(idempotency_key)` 仅非唯一索引，commit/release 为 SELECT→INSERT 非原子；失败键复用不清理导致永久漏退积分。**正在持续资损**。（FIN-01/02/03）

3. 🔴 **【P0·资金】T1 bug + webhook 绕 billing 入账**
   minimax/volcano 明确失败返 `error` 被当瞬时错误 failover 空转，全失败入 `waiting` 致积分永不释放；webhook 裸 SQL 直接入账，与 billing 双路径语义漂移。（FIN-04/05、PERF-03）

4. 🔴 **【P0·认证】JWT 默认弱密钥 `'dev-only-change-me'` 可伪造 + `GET /api/oss` 泄露 OSS 密钥**
   `.env` 无 `JWT_SECRET` → 可离线伪造任意 `role:'admin'` 会话；`/api/oss` 仅需登录即明文返回 `accessKeySecret`。两者叠加构成认证绕过 + 凭据泄露。（SEC-02、SEC-05）

5. 🔴 **【P0·契约】前后端隐藏契约脆弱（canceled/cancelled、错误字符串、SNAKE_MAP）+ 重构无测试安全网**
   取消拼写不一致致跨标签取消失效；错误以"字符串+状态码"当协议，改任一文案即静默断连；`SNAKE_MAP` 缺口致前端字段 `undefined` 假死；且 `npm test` 框架与实际测试不匹配（vitest vs node:test），资金/状态机零测试。**重构前必须先锁定契约 + 补字符化测试，否则改动即引入难查回归**。（FE-01~04、RT-01、TEST-01~03/05）
