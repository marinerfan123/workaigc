## 2. 关键事实澄清（来自源码，非推断）

- **Redis 持有 0 关键数据（可安全 flush）**：`redis.cjs` 的 `kvGet/kvSet/kvIncr/kvExpire` 在 Redis 不可用时自动降级到内存 `Map`，且全程仅服务限流/缓存/队列。任何关键业务状态（任务、余额、账务）均在 PG。【源码已证实】高。运维侧"8 个孤儿 key"为运行时观察，本审计未连接验证（【运行时已证实(运维侧)·待核验】中）。
- **dispatcher 任务应 PG 持久化（核实 server.js/dispatcher.cjs）**：`dispatcher.cjs` 所有任务生命周期（创建/轮询/resume/终态/释放）均读写 `generation_tasks`，崩溃可由 `generation_tasks` 捞回。`server.js:301` 对 `generation_tasks.idempotency_key` 建**唯一索引** `ux_gt_idem`，任务级幂等由 DB 强制。【源码已证实】高。
- **initDB 失败 exit(1) 行为**：确为 `server.js:104` 与 `server.js:813` 两处 `process.exit(1)`；schema 定义含 **40 个 `CREATE TABLE IF NOT EXISTS` + 65 个 `ALTER TABLE`**（L78–L813 区间统计），全部幂等，重启可安全重建/补齐列。【源码已证实】高。

## 3. 已证实 vs 未知 汇总

**已证实（源码）**
- 存在手动 PG 逻辑备份/恢复脚本（backup-db.cjs / restore-db.cjs）。
- 无 WAL 归档、无流副本、无故障转移（compose 仅有单 postgres + 单卷）。
- Redis 仅缓存/限流，关键数据全在 PG；compose 开 AOF。
- dispatcher 任务 PG 持久化可捞回；initDB 失败 exit(1)；PM2 单实例自动重启。
- 部署无版本标签/回滚机制；备份与库同机、未加密。

**未知·待核验**
- PG 是否在生产环境有**定时自动备份**调度（脚本存在但无调度证据）。
- OSS 对象是否有跨区复制/版本控制备份。
- 备份是否异地、加密、保留周期；是否做过恢复演练；RTO/RPO 目标。
- Redis "8 个孤儿 key" 的实时计数（本审计未连接 Redis）。

## 4. 审计发现摘要（最关键风险 5 条）

1. **数据库单点 + 无副本/PITR**：compose 仅单 postgres 容器挂单卷，无 WAL 归档、无流副本、无故障转移，RPO 取决于备份频率。【源码已证实·高】
2. **仅手工备份、无自动调度**：backup 脚本存在，但无 cron/CI 定时证据，仅有 2026-08-06 三次快照，无持续 RPO 保障。【未知·待核验·中】
3. **备份与库同机、未加密**：`backups/db/` 与 PG 同机，ndjson 明文、无异地/加密，单点失效即备份同损；`.env` 密钥亦未纳入备份。【源码已证实·高】
4. **部署无回滚机制**：docker-compose/Dockerfile 无镜像版本标签与回滚策略，故障回退只能手动重 build 旧版。【源码已证实·高】
5. **OSS 对象备份未知**：业务资产全在外部 OSS，源码无法证实其跨区复制/版本控制，存在对象级丢失风险敞口。【未知·待核验·中】
