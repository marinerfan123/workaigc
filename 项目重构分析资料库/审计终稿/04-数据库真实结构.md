## 5. 关键 JSONB 字段真实结构【源码已证实 + 数据库已证实】
- `generation_tasks.result` (jsonb)：生成成功后的资产 URL/元数据数组（dispatcher 写入）。
- `generation_tasks.client_meta` (jsonb)：前端透传的客户端元信息（占位 item 等）。
- `generation_tasks.resume_meta` (jsonb)：**崩溃恢复核心**——含 `submittedAt`、`waitingOpts`（等待区持久化）等；重启据此重建轮询端点（dispatcher `resumeRunningTasks`/`resumeWaitingArea`）。
- `recharge_orders.meta` (jsonb)：订单扩展；`channel_raw` (jsonb)：支付渠道原始回执。
- `payment_providers.supported_methods` (jsonb)：支持支付方式列表。
- `settings.app` (jsonb，推断自代码引用 `settings.app.*`)：站点级配置（含 `styleCommissionRate` 默认 30%、`defaultBackendCost`、`maxThreads` 等）。
- 其余表以标量列为主。

## 6. 约束与索引缺口（P0 资金安全）【数据库已证实】
1. **`credit_transactions` 无 (ref, kind) 唯一约束**：仅非唯一索引 `ix_ct_ref`。`billing.cjs` 的 `_hasPosted(ref,kind)` 为 SELECT→INSERT 两步、非原子 → **TOCTOU 重复退款/重复记账风险（P0）**。
2. **`consumption_ledger.idempotency_key` 仅非唯一索引 `ix_cl_idem`**：`accounting.recordConsumption` 同键 SELECT→INSERT 无事务 → **并发双记账、margin 虚高风险（P0）**。
3. **`users.credits` 为 GENERATED ALWAYS 生成列**：不可写、不可扣 → 双余额实为 `reward_credits`+`recharge_credits` 两真实池，"三余额"无经 credits 双花风险（已证实，解除误判）。
4. **`media.user_id` / `reference_style_id` 外键为 `ON DELETE SET NULL`**：删用户会留孤儿媒体（user_id 置 NULL），非级联删除 → 数据完整性需注意（P2）。
5. `generation_tasks.idempotency_key` 有**唯一索引** `ux_gt_idem`（WHERE NOT NULL）→ 任务级幂等兜底有效。
