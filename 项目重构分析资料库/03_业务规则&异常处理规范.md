# PART A · 🟥 业务规则（重构必须原样保留）

## A1 计费三段式时序 + 幂等（G3 计费铁律）
- **规则**：一次生成只扣一次费，分三段——`reserve`（提交即扣，仅扣到解析出的池）→ `commit`（成功结算）/ `release`（失败/取消/异常回退）。reserve 只在 `/api/generate` handler 发生，commit/release 只在 dispatcher 后台回调发生。
- **跨文件调用链**：
  `server.js:2431 reserveCredits` → `dispatcher.generateAsync` 后台跑 → 成功 `billing.commitCredits`(dispatcher.cjs:688) / 失败 `billing.releaseCredits`(L731) / 异常 `releaseCredits`(L755) / 取消 `cancelTask` 内 `releaseCredits`(dispatcher.cjs:1240)。
- **源码**：billing.cjs:32/58/70；幂等靠 `credit_transactions.ref+kind` 唯一（`_hasPosted` L48）。
- **设计依据**：reserve 不结算、结算留后台，是为了让「崩溃/超时」能安全 release，避免用户被白扣。
- **重构备注**：🟥 时序、双池、幂等键（`idempotency_key`）不可改；可换存储但语义必保。

## A2 双余额：奖励优先、回退充值
- **规则**：解析扣费池时 `supportsReward ? (reward>=required→reward池 : recharge>=cost→recharge池) : (recharge>=cost→recharge池)`，都不够抛 `INSUFFICIENT`/`NEED_RECHARGE`。`users.credits` = reward_credits + recharge_credits（STORED 列）。
- **跨文件调用链**：`server.js:2418 resolvePayment` → `billing.resolvePayment`(billing.cjs:11) → `reserveCredits(pool)`(server.js:2431)。
- **源码**：billing.cjs:11-29；前端 `checkBalance`(GenerationBar.tsx:980) 做一致的前置校验（优先赠送→回退充值→都不够拦截）。
- **重构备注**：🟥 优先序、两池回退逻辑不可改；🟩 余额展示三元徽章 UI 可重做。

## A3 成败只听生成端终态（超时铁律）
- **规则**：任务成败**只能**以生成端终态（success/failed）为准；固定时间只作防僵尸安全线（默认 90min）。超时**绝不判失败、绝不退积分**，标 `timeout`/`waiting` 保留待复核。
- **跨文件调用链**：`videoGenerate` 内 `deadline=90min`(dispatcher.cjs:266) → pollLoop 超返 `timeout`(shared.cjs:222) → `attemptOnAccount` 透传 timeout(L485-493) → `generate` 返 timeout(L636) → `generateAsync.then` 标 `waiting` 不释放(L725) → `finalizeResumedTask` 同(L942)。
- **设计依据**：避免「生成端其实还在跑、我们却按时间判失败退积分」导致用户损失 + 资产丢失（#578 教训）。
- **重构备注**：🟥 90min 安全线数值、超时返 timeout 语义、waiting 保留不可改；🟩 安全线时长可配置。

## A4 幂等键防双扣（G4）
- **规则**：每次生成请求前端生成 `idempotencyKey`（UUID），后端必需；同键 running/done 直接返回原 taskId（绝不重复 reserve），failed 则释放旧 held + 删行重试。
- **跨文件调用链**：`GenerationBar` 生成 `crypto.randomUUID()`(L1087，非安全上下文降级) → `apiGenerate.idempotencyKey` → `server.js:2391` 查重 → `billing.commit/release` 以 `idemKey` 为 ref 幂等。
- **源码**：server.js:2386-2406；billing.cjs _hasPosted(L48)。
- **重构备注**：🟥 幂等语义不可改；🟩 randomUUID 降级方案可优化。

## A5 等待区 + 会员优先调度
- **规则**：某任务所有供应商都不可用（dispatchOne 全拒→`throttled`）时，不立即失败，进等待区后台重试（runWaitingPump）；会员（pro/team）出队优先级高于 free（PLAN_PRIORITY L1102）。全部资源不可用且积压>阈值(默认10)→前台提示「资源不足」。
- **跨文件调用链**：`generate` 返 throttled(L639) → `generateAsync.then` `enqueueWaiting`+`persistWaitingOpts`(L713-715) → `runWaitingPump`(L1257) 重试 → 成功 commit / 仍 throttled 留区 / 失败 release。
- **源码**：dispatcher.cjs:1102/1106-1109/1138/1154/1175/1257。
- **设计依据**：把「资源不足」从痛点转成付费理由（会员优先抢恢复资源），同时不误伤用户（不立即失败）。
- **重构备注**：🟥 等待区不退费、会员优先次序、阈值语义不可改；🟩 内存 Map 可换 Redis。

## A6 崩溃恢复（视频续轮询 + 等待区重建）
- **规则**：视频提交成功即持久化 `provider_task_id`+`resume_meta.submittedAt`（dispatcher.cjs:776 persistProviderTaskId）；进程启动扫 `running`+有 provider_task_id 且 6h 内任务，`resumeOneTask` 续轮询（L795/863）。等待区孤儿（resume_meta.waitingOpts 或 error 含「等待区」）重启后 `resumeWaitingArea` 重入队（L822）。
- **跨文件调用链**：`videoGenerate.onSubmitted`→`persistProviderTaskId`→ DB → server.js 启动 `resumeRunningTasks` → `resumeOneTask` → `videoRouter.poll`/`genericVideoPoll` → `finalizeResumedTask`（与正常完成同逻辑）。
- **源码**：dispatcher.cjs:776/795/822/863/907；server.js 启动流程调用。
- **设计依据**：进程崩溃/重启后内存轮询态丢失，但 provider 任务仍在跑，必须靠 PG 里的 provider_task_id 捞回结果，否则那笔生成白做、积分卡 held（出错点 H/K）。
- **重构备注**：🟥 「提交即落 provider_task_id + 启动时续轮询 + 等待区持久化」是业务规则；🟩 扫描 SQL 窗口（6h/3h）可调。

## A7 取消端点终态（I）
- **规则**：`POST /api/generate/cancel/:taskId` → owner 校验 → 写 `cancelledTasks` Set（停轮询）→ 出等待区 → 释放 held → 标 `canceled` → 推 SSE。`generateAsync.then`/`finalizeResumedTask` 顶部加 `cancelledTasks` 护栏，覆盖图片等无 poll 路径（dispatcher.cjs:674/910）。
- **源码**：server.js:2506 → dispatcher.cancelTask(L1216)；终态码 200/404/403/409/500/503。
- **设计依据**：权威终态（释放+标记+推送）由 cancelTask 一次性完成，pollLoop 只停轮询（出错点 I）。
- **重构备注**：🟥 释放 held + owner 校验 + 终态不可取消（done/failed/canceled→409）不可改。

## A8 权限 / owner 校验（G1 防串看）
- **规则**：任务严格按 `user_id` 归属；SSE 按 userId 订阅（realtime L30）；listActiveTasks 按 userId 过滤（dispatcher.cjs:1043）；cancel 校验 owner（dispatcher.cjs:1227→403）。
- **重构备注**：🟥 所有任务/资产查询必须带 user_id 过滤，禁止跨用户可见。

## A9 SNAKE_MAP 契约（B）
- **规则**：PG snake_case ↔ 前端 camelCase 的唯一映射表，双向（fromSnake L808 / toSnake L816）。新增 DB 列必须同步，否则前端字段 undefined 假死。
- **源码**：server.js:780-823。
- **重构备注**：🟥 映射表不可丢；换 ORM 时须保留等价字段别名。

## A10 支付 fail-closed（四）
- **规则**：无 payment provider 时 `createOrder` 一律 503；`loadPaymentSettings` 缺配置/异常返回 null→503；webhook `/api/credits/webhook/:type` 四道闸门 fails-closed（异常即拒，不静默成功）；易支付密钥 AES-256-GCM 加解。
- **源码**：payments.cjs:34/59；seed-easypay.cjs；server.js webhook 路由。
- **重构备注**：🟥 fails-closed 不可改（绝不允许「支付成功但未校验」）；🟩 加密库/支付渠道可换。

## A11 全局双边记账无例外（账务铁律）
- **规则**：所有模型消耗（含系统自身）都走 `accounting.recordConsumption`，双边（后台量×客户量），差值=盈亏；幂等 + try/catch 不阻断主链路。generate/skill:*/agent:optimize-prompt 强制埋点。
- **源码**：accounting.cjs:55；dispatcher 成功分支 L695/927/1289。
- **重构备注**：🟥 强制埋点、双边算量不可省；系统调用 scope='system' 客户收费传 0。

## A12 OSS 零二进制 + 成功即存（已落地）
- **规则**：业务服务器不存任何二进制，只持预签名 URL；用户资产成功即传 OSS 落 `oss_url`。第三方 URL 存外网，用户资产存 OSS。
- **重构备注**：🟥 零二进制原则 + 成功即落 OSS 不可改；🟩 OSS 厂商/SDK 可换。

## A13 同步通道兼容
- **规则**：`body.sync=1` 时 `/api/generate` 直接 `dispatcher.generate` 同步返回完整结果（仍走计费，server.js:2462）。保留以兼容老客户端/测试。
- **重构备注**：🟥 同步等价语义（计费一致）必须保留；🟩 可仅留异步。

## A14 前端乐观 UI + 刷新恢复
- **规则**：提交即建 N 个 pending 占位（乐观 UI），回写 taskId，写 localStorage；刷新后由 localStorage + `/api/generate/active` 双路恢复（GenerationBar useEffect L1206）。
- **源码**：GenerationBar.tsx:1049-1168 / 1206。
- **重构备注**：🟥 「pending 占位不被误判 failed」「刷新可续上」是业务规则；🟩 localStorage 可换 IndexedDB/服务端 session。

# PART C · 出错点防复发速查（A–K + 关键 issue）

> 每条含：现象 → 根因 → 修复 → 触发条件。重构时对照避免重犯。

- **A. 网站打不开先二分**：根因多为 agent 后台进程不跨会话存活（2026-08-11 复现）。先确认 3001/5173 端口在 LISTENING（`netstat`），再怀疑代码。stable 使用必须在用户本机 `npm run dev`；沙箱 `curl localhost` 不可靠。
- **B. SNAKE_MAP 遗漏**：新增 DB 列未同步 server.js SNAKE_MAP → 前端字段 undefined 假死（A9）。改动后必查双向映射。
- **C. 成败以生成端终态为准（#578）**：补齐两处真缺口——dispatcher generic 视频路径 20min→90min；attemptOnAccount/dispatchOne/generate 不再把 timeout 折叠成 throttled 重轮询。
- **D. 双积分**：三元徽章；后台填双积分后 SNAKE_MAP 须含 `supports_reward_balance`/`reward_credits_required`（A2）。
- **E. 删/写库后前端必须真调 API 并主动刷新计数/列表**：不能只改本地 state。
- **F. 不给 pending 虚假百分比**：indeterminate 扫光 + 真实已等待时间（视频提示「预计7-15分钟」），绝不用伪进度。
- **G. 图片破图**：ui/image.tsx errored 分支须随 src 重置（`useEffect(()=>setErrored(false),[src])`，2026-08-11 修复）。数据根因：OSS 私有 bucket 403 / 预签名 7天过期 / 服务商临时 URL 更快过期 / data URI 落库。修复：OSS public-read 或挂 CDN；provider 临时 URL 尽快传 OSS；OSS 未开提示而非存 data URI。
- **H. 崩溃恢复续轮询**：视频在途 provider_task_id 落库，server.js 启动 resumeRunningTasks 续轮询（A6）。
- **I. 取消端点（#592–#597）**：POST /api/generate/cancel/:taskId → cancelTask（owner 校验→cancelledTasks→释放积分→标 canceled→SSE）。generateAsync.then/finalizeResumedTask 顶部护栏覆盖图片路径（A7）。
- **J. 视频 failed 透传 + 孤儿看门狗（#602/#603）**：生成端明确 failed 立即终态化（释放积分+推 failed），不再当瞬时 error 切下一账号空转（dispatcher.cjs:497-506）；startStuckTaskWatchdog 每 10min 扫 running>3h 强制 failed+释放（仅回收孤儿，不碰 waiting，L978-1009）。⚠️ **已核验缺口（2026-08-11，T1）**：MiniMax/Volcano 适配器 poll 检测 failed 时返 `error` 而非 `failed`（minimax.cjs:85 / volcano.cjs:121），会被 attemptOnAccount:507 当瞬时错误切下一账号——#602 修复对这两个适配器**不生效**，仅 generic 路径（dispatcher.cjs:289）生效。重构时必须修复或显式记录。
- **K. 等待区崩溃恢复（#604）**：WAITING_AREA 原纯内存 Map，重启丢→孤儿。persistWaitingOpts 存 resume_meta + resumeWaitingArea 启动重入队（A5/A6）。

### 工程纪律（跨项目）
- **修复后必验服务启动/重启**（铁律）：后端改动必须重启 3001 加载新代码，否则「改了等于没改」；前端改完需 vite 重编译 + 强刷。
- **tsc 宽松 ≠ vite 严格**：多轮 Edit 同文件后必 Read import 块查重复声明（否则 vite 炸 Identifier already declared）。
- **Git safe-git**：写 .git/ 必须走 plumbing（buildtree.cjs + _mk/*.sh），dangerouslyDisableSandbox，父提交取 ls-remote，远程即权威。
