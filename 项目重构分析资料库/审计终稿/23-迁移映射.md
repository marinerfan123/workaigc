# 23 · 迁移映射（旧 → 新）

> 与 `22-目标架构建议.md`、`24-重构Phase计划.md` 配套。本文给出「现状（旧）」到「目标态（新）」的逐模块/表/API/前端路由迁移映射，并标注**迁移难度（高/中/低）、风险、建议顺序（对应 Phase0–Phase5）**。
> 只读依据：`审计终稿/02-15`、`项目重构分析资料库/00-06`、`07_PG_schema快照.sql`，及对 `server/server.js`、`server/billing.cjs`、`package.json` 的回查。
> **铁律遵守**：未修改 `E:\code` 任何文件。
> 证据等级/置信度见每条。

> 难度图例：**高**=需改数据模型/事务/跨多模块，回归面大；**中**=需局部重构+契约对齐；**低**=机械平移或纯结构整理。
> 建议顺序：`P0`冻结+测试网 / `P1`资金安全 / `P2`安全加固 / `P3`解耦契约 / `P4`目标架构落地 / `P5`切换下线（详见 24）。

## A. 后端中央 handler → 模块化 router

| 旧（现状） | 新（目标态） | 难度 | 风险 | 建议顺序 | 证据 |
|---|---|---|---|---|---|
| `server.js` 单体 `handleAPI`（L1573–3607，>1000 行 if/else 路由分支 + 内联业务 + 错误拼装） | 注册式 `RouterTable`：`registerRoute(method, path, handler, {auth, scope})`，中央 `http.createServer` 仅做分发 + 统一 `appGateway` + 统一错误中间件 | 高 | 路由覆盖遗漏导致 404/回归；需 Golden Master 基线比对 | P4 | 【源码已证实】HIGH（03/02 F-xxx）+【硬约束】HIGH |
| 鉴权散落：`appGateway`(L1274) + 各分支 `requireAdmin` + 手动 owner 校验 | 统一 `requireScope(role, resource, action)`；owner 由 DAL `WHERE user_id=$1` 强制 | 中 | 权限回归（误放/误拒） | P2/P4 | 【源码已证实】HIGH（03 §3） |
| 错误拼装散落各处（`{error}`/`{ok:false}`/`API <status>:` 文本） | 统一 `ErrorEnvelope` 中间件：`{ok, code, message, data?}`，`code` 枚举化 | 中 | 前端契约断裂（见 §E、§D） | P3 | 【源码已证实】HIGH（12 C1/C2/C3） |
| `admin.cjs` 巨型 `handleAdmin` switch（~40 分支） | `registerModule`（L0–L3）驱动，模块自声明 routes/permissions | 中 | 后台功能遗漏 | P4 | 【源码已证实】HIGH（02 F-051 等） |

> 注意：技术栈硬约束要求「**后端 Node 原生 HTTP 中央 handler 分发**」保留——即中央入口与统一鉴权/错误中间件**不拆掉**，只是把巨函数拆成注册式路由表。二者不冲突。
