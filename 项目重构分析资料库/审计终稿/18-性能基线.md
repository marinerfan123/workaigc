> 范围：墨灵 AI（AI 图像/视频生成工作室）后端 `server/` + 前端 `src/` `dist/`

## 3. 性能风险清单（按 P0 / P1 / P2）

### P0（上线/扩展前必须解决）
1. **单进程实时总线限制横向扩展** — realtime SSE 连接、dispatcher 令牌桶、ACCT、WAICTING_AREA、GLOBAL_ACTIVE 全部为进程内存态；PM2 已锁 `instances:1`。多实例会丢事件、重复扣桶、状态分裂。证据：`server/realtime.cjs`、`server/dispatcher.cjs:39-42`、`deploy/ecosystem.config.cjs`。证据等级：源码已证实。置信度：高。
2. **SSE 连接数无上限 / 无背压** — `realtime.cjs` 仅 `conns.set(userId).add(res)`，`setMaxListeners(0)`；高并发下每个用户多个标签页/刷新会堆积连接与事件回调，广播为 O(连接数) 同步 `write`，可能拖垮事件循环。证据：`server/realtime.cjs:14,30-49`。证据等级：源码已证实。置信度：高。
3. **单体前端包 4.35MB + 开启 sourcemap 生产构建** — 无代码分割/懒加载，首屏需下载并解析整包；`.map` 同体积外发，既拖慢加载又暴露源码。证据：`dist/build2/`、`vite.config.ts`。证据等级：源码已证实。置信度：高。

### P1（应在重构周期解决）
4. **SNAKE_MAP 逐行字段转换 CPU 开销** — 每次查询均逐键映射；`toSnake()` 每次重建反向 Map（可缓存）。高频列表/状态接口叠加明显。证据：`server/server.js:830-873`。证据等级：源码已证实。置信度：中。
5. **计费/账务缺显式事务** — `reserve/commit/release`、`recordConsumption` 走「单条原子 UPDATE + 幂等流水/INSERT」而非事务；正常路径靠幂等与 `WHERE col>=amount` 兜底，但崩溃于 UPDATE 与流水 INSERT 之间会出现「扣了余额但未记账」或反之的短暂不一致，依赖后台 `findDanglingReserves` 兜底（L2/L3 worker，非实时）。证据：`server/billing.cjs`、`server/accounting.cjs`、缺 L1 实时对账。证据等级：源码已证实 + 推断。置信度：中。
6. **initDB 启动开销随版本膨胀** — 20+ 表 + 多段 ALTER 兼容迁移 + 种子回填，每次启动串行执行；冷启动慢、迁移脚本与表定义双份维护易漂移。证据：`server/server.js:78-340`。证据等级：源码已证实。置信度：中。
7. **provider 同步等待 + 长轮询占池** — 视频任务在进程内 `while` 轮询至多 90 分钟（每个活跃任务长期占用 Node 事件循环协程与 PG 连接）；全局并发仅 10，单账号 4，重负载下易触等待区。证据：`server/dispatcher.cjs`、`server/providers/video/shared.cjs`。证据等级：源码已证实。置信度：中。
8. **双 Redis 实例并存** — `db.cjs` 自带一个 `ioredis`（`maxRetriesPerRequest:3`，无降级），与 `redis.cjs`（带内存兜底）并存，连接/配置/限流语义不统一。证据：`server/db.cjs:23-33` vs `server/redis.cjs`。证据等级：源码已证实。置信度：中。

### P2（优化项）
9. **启动期循环逐行写（伪 N+1）** — seed/default_assets/setup 向导在循环内 `await pg.query`，虽非热路径但拉长首启与首次部署时间。证据：`server/server.js:922-924,962-967,1543-1547`。证据等级：源码已证实。置信度：中。
10. **监控指标为进程内存环形缓冲** — monitor/logbus 各 500/1000 条环形缓冲、SSE 广播，进程重启即清零，**无 Prometheus/metrics 端点**，无法跨实例聚合、无历史留存。证据：`server/monitor.cjs`、`server/logbus.cjs`。证据等级：源码已证实。置信度：高。（性能侧影响：无指标→无法量化瓶颈、无法设告警阈值）
11. **媒体列表 OSS 重签循环** — `/api/media` 对返回列表逐条 HMAC 重签（纯 CPU 无网络，但有 >1 天有效期跳过逻辑），列表大时累积开销。证据：`server/server.js:1950-1972`。证据等级：源码已证实。置信度：中。

## 5. 摘要

墨灵 AI 后端为**单进程 Node + PostgreSQL + Redis（可降级）** 架构，调度层（令牌桶/全局信号量/等待区/SSE 总线）全部进程内存态，部署上已被 PM2 `instances:1` 强制锁定——这是当前最大性能天花板：**无法横向扩展**，实时事件与限流状态随实例数分裂。provider 调用 60s 超时、视频 90min 安全线（防僵尸、不判失败）设计合理，但**长轮询占用进程协程**与全局并发仅 10 会放大等待区积压。计费靠「原子 UPDATE + 幂等流水」而非事务，正常路径安全但缺实时对账（仅 L2/L3 兜底）。

前端为**单一 4.35MB 包、无代码分割、生产开启 sourcemap**，首屏下载/解析成本高、源码外发。

实测仅验证后端根与 Vite 根可达（HTTP 200，RTT 量级 210ms / 4ms），**业务接口 P95、provider 端到端、首屏 TTI 等需压测/tracing，本环境标【未知·待核验】**。

重构优先级：P0 解决「单实例扩展锁 + SSE 连接无上限 + 前端单体包」；P1 优化 SNAKE_MAP、补齐事务化计费与实时对账、收敛 initDB、统一 Redis 实例；P2 清理启动期循环写与监控持久化。
